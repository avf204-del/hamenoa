# פריסה ל־Railway

המאגר הזה עדיין לא פרוס בשום מקום. האתר החי ממשיך לרוץ מהמאגר הקודם (`avf204-del/forceapp`), ושום דבר כאן לא נוגע בו. פריסה לייצור, שינוי סכמה או חיבור למסד הקיים דורשים אישור מפורש של הבעלים. היסטוריית הפריסות של האתר החי נשארה במאגר הקודם.

## סביבת ניסיון: הקמה חד־פעמית

המטרה: שירות נפרד, עם מסד נפרד, שנפרס מהמאגר הזה. כך אפשר לעשות אימון אמיתי בטלפון בלי לסכן את האתר החי ואת נתוני המשתמשים.

שמות הכפתורים ב־Railway משתנים מעט מעת לעת; מה שחשוב הוא מה שכל צעד משיג.

1. **שירות חדש מהמאגר.** בפרויקט ב־Railway: New ← GitHub Repo ← `avf204-del/hamenoa`, ענף `main`. שם מוצע: `hamenoa-next`.
2. **מסד חדש.** באותו פרויקט: New ← Database ← PostgreSQL. זה מסד ריק ונפרד. לא מחברים את השירות החדש למסד של האתר החי.
3. **משתנים**, בלשונית Variables של השירות החדש:

   | משתנה | ערך |
   | --- | --- |
   | `DATABASE_URL` | הפניה למסד החדש, למשל `${{Postgres.DATABASE_URL}}` (לפי שם שירות המסד אצלך) |
   | `APP_PASSWORD` | סיסמה ארוכה חדשה, שונה מזו של האתר החי |
   | `AUTH_SECRET` | מחרוזת אקראית ארוכה |
   | `OPERATOR_NAME` | השם שמופיע בתנאים ובפרטיות |
   | `APP_URL` | הכתובת הציבורית של השירות החדש (אחרי צעד 5) |

   כניסה בגוגל אינה נדרשת לסביבת הניסיון. בלי `GOOGLE_CLIENT_ID` ו־`GOOGLE_CLIENT_SECRET` נכנסים בסיסמה.
4. **פקודות**, בהגדרות השירות (Settings):

   | הגדרה | ערך |
   | --- | --- |
   | Build | ברירת המחדל (`pnpm run build`) |
   | Pre-deploy command | `TZ=Asia/Jerusalem pnpm run deploy:prepare` |
   | Start command | `TZ=Asia/Jerusalem pnpm exec next start` |
   | Restart policy | On failure |

   שלב ה־pre-deploy מריץ את המיגרציות וטוען את מאגר התרגילים. אם הוא נכשל, הגרסה החדשה לא עולה.
5. **כתובת.** בהגדרות הרשת של השירות (Networking): Generate Domain. את הכתובת שמתקבלת מעתיקים ל־`APP_URL`.
6. **בדיקה.** בלוגים של הפריסה הראשונה: המיגרציות הסתיימו ו־283 תרגילים נטענו. אחר כך פותחים את הכתובת בטלפון, נכנסים בסיסמה, מאשרים תנאים ושאלון בריאות, ובונים אימון.

כל דחיפה ל־`main` במאגר הזה תפרוס מחדש את סביבת הניסיון. בסביבה הזו אין גיבוי אוטומטי; הנתונים בה הם נתוני ניסיון.

## לפני ייצור

המעבר לייצור הוא שלב 11 ב־[התוכנית](../PLAN.md), ולא חלק מהקמת סביבת הניסיון. לפניו צריך:

- גיבוי טרי של המסד החי ובדיקת שחזור, לפי [מדריך האחסון](STORAGE.md).
- החלטה איך מועברים המשתמשים הקיימים: הסכמה זהה, כך שאפשר לחבר את המאגר הזה למסד הקיים. אימונים מהגרסה הקודמת יישארו במסד ולא יוצגו.
- שירות גיבוי יומי: שירות cron נפרד עם volume ב־`/data`, שמריץ `pnpm db:backup --dir /data/backups --keep 30`.
- משתני גוגל (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`) והכתובת הסופית ב־`APP_URL`.

בייצור חובה להגדיר `APP_PASSWORD`; בלעדיו השרת מחזיר 503 בכוונה. יתר המשתנים מתועדים ב־`.env.example`.
