# איך מפעילים את האפליקציה: מדריך למי שלא מגיע מהעולם הטכני

המדריך הזה מסביר, צעד אחרי צעד, איך לוקחים את הקוד של "המנוע" ומגיעים לאפליקציה שרצה ואפשר להתאמן בה. הוא כתוב למי שמעולם לא הריץ תוכנה מקוד, ולכן הוא ארוך. מי שכבר יודע מה זה טרמינל יכול לקפוץ ישר ל־[README](../../README.md).

בכל מקום שבו יש שתי דרכים לעשות משהו, המדריך מסביר את ההתלבטות ואומר מה מומלץ.

## 1. מה בכלל צריך לקרות כדי שהאפליקציה תעבוד

האפליקציה מורכבת משלושה חלקים, וכולם חייבים לרוץ ביחד:

1. **הקוד של האפליקציה.** זה מה שנמצא במאגר הזה. הוא יודע לבנות אימון ולהציג מסכים.
2. **מסד נתונים.** כאן נשמרים המשתמשים, האימונים ומאגר 283 התרגילים. בלי מסד האפליקציה לא עולה.
3. **שרת שמגיש את זה לדפדפן.** תוכנית שרצה ברקע ומחכה שמישהו יפתח את הכתובת שלה בדפדפן או בטלפון.

"להפעיל את האפליקציה" פירושו להרים את שלושת החלקים האלה. יש שלוש דרכים לעשות את זה, והבחירה ביניהן היא ההתלבטות הראשונה.

## 2. ההתלבטות הראשונה: איפה מריצים

| דרך | מה זה | מתי מתאים | חסרונות |
| --- | --- | --- | --- |
| **א. על המחשב שלך** | מתקינים כלים על המחשב ומריצים הכול מקומית | לעבודה יומיומית ולבדיקות בדפדפן | דורש התקנה חד־פעמית; הטלפון לא רואה את זה בלי טריקים |
| **ב. בענן של GitHub (Codespaces)** | GitHub פותח לך מחשב וירטואלי בדפדפן, הכול כבר מותקן | למי שלא רוצה להתקין כלום | הכתובת זמנית; המסד מתאפס כשהסביבה נמחקת |
| **ג. שרת אמיתי (Railway)** | האפליקציה עולה לכתובת קבועה באינטרנט | לאימון אמיתי בטלפון, בחדר כושר | דורש חשבון Railway, עולה כסף קטן, ומחייב זהירות כדי לא לפגוע באתר החי |

**המלצה:** אם המטרה היא לראות את האפליקציה ולבדוק אותה, מתחילים בדרך א' או ב'. אם המטרה היא אימון אמיתי בטלפון, זו דרך ג', לפי סעיף 6.

חשוב לדעת: האתר החי של המנוע רץ היום מהמאגר הקודם (`forceapp`), לא מהמאגר הזה. שום דבר במדריך הזה לא נוגע באתר החי. כל מה שמריצים כאן הוא סביבה נפרדת עם מסד נפרד.

## 3. מילון קצר

- **טרמינל** (או "שורת פקודה"): חלון שבו כותבים פקודה בטקסט ולוחצים Enter. במק הוא נקרא Terminal, בווינדוס מומלץ PowerShell. כל הפקודות במדריך נכתבות בו.
- **פקודה**: שורת טקסט שמקלידים בטרמינל. מעתיקים אותה בדיוק כמו שהיא, בלי לשנות.
- **Node.js**: התוכנה שיודעת להריץ את הקוד של האפליקציה. צריך גרסה 22 או חדשה יותר.
- **pnpm**: כלי שמוריד את כל הספריות שהאפליקציה צריכה ומריץ את הפקודות שלה. משתמשים רק בו, לא ב־npm ולא ב־yarn.
- **localhost:3000**: הכתובת של האפליקציה כשהיא רצה על המחשב שלך. פותחים אותה בדפדפן כמו כל אתר.
- **משתנה סביבה**: הגדרה שנותנים לאפליקציה מבחוץ, כמו סיסמה או כתובת של מסד. בפיתוח מקומי לא צריך להגדיר אף אחד.
- **Ctrl+C**: הדרך לעצור תוכנית שרצה בטרמינל.

## 4. דרך א': הרצה על המחשב שלך

### 4.1 התקנה חד־פעמית (עושים פעם אחת)

**שלב 1: להתקין Node.js.**
נכנסים ל־nodejs.org ומורידים את הגרסה המסומנת LTS (צריך 22 ומעלה). מתקינים כמו כל תוכנה. אחרי ההתקנה פותחים טרמינל ומקלידים:

```sh
node --version
```

אם מופיע מספר שמתחיל ב־22 או יותר, הכול טוב. אם מופיעה שגיאה "command not found", סוגרים את הטרמינל, פותחים מחדש ומנסים שוב. אם עדיין לא, ההתקנה לא הושלמה.

**שלב 2: להתקין Git ולהוריד את הקוד.**
Git הוא הכלי שמוריד את הקוד מ־GitHub. במק הוא כנראה כבר מותקן; בווינדוס מורידים מ־git-scm.com. אחר כך, בטרמינל, עוברים לתיקייה שבה רוצים את הקוד (למשל "מסמכים") ומקלידים:

```sh
git clone https://github.com/avf204-del/hamenoa.git
cd hamenoa
```

הפקודה הראשונה מורידה את הקוד לתיקייה בשם `hamenoa`. השנייה נכנסת לתוכה. מעכשיו כל הפקודות במדריך מניחות שאתם בתוך התיקייה הזו.

**שלב 3: להפעיל את pnpm ולהוריד את הספריות.**

```sh
corepack enable
pnpm install
```

הפקודה הראשונה מפעילה את pnpm (הוא מגיע עם Node.js, רק צריך להדליק אותו). השנייה מורידה כמה מאות ספריות שהאפליקציה תלויה בהן. זה לוקח דקה או שתיים ומדפיס הרבה טקסט. זה תקין. אם בסוף יש שורה אדומה עם המילה ERROR, מעתיקים אותה ומבקשים עזרה.

התקנת הכלים הסתיימה. את שלושת השלבים האלה לא צריך לחזור עליהם.

### 4.2 הפעלה (עושים בכל פעם שרוצים לעבוד)

**ההתלבטות: למה צריך שני חלונות טרמינל?**
מסד הנתונים והשרת הם שתי תוכניות נפרדות, וכל אחת תופסת את הטרמינל שבו היא רצה. לכן פותחים שני חלונות: אחד למסד ואחד לשרת. שניהם צריכים להיות בתוך תיקיית `hamenoa`.

**חלון 1: המסד.**

```sh
pnpm db:local
```

כשמופיעה השורה "Postgres מקומי (PGlite) עלה", המסד רץ. משאירים את החלון פתוח ולא נוגעים בו. אם סוגרים אותו, האפליקציה מפסיקה לעבוד.

המסד הזה לא דורש התקנה: הוא מסד Postgres שרץ מתוך Node.js ושומר את הנתונים בתיקייה `prisma/local-pg` שבתוך הפרויקט. הנתונים נשמרים בין הפעלות.

**חלון 2 (בפעם הראשונה בלבד): הכנת המסד.**

```sh
pnpm db:setup
```

זה יוצר את הטבלאות ומכניס את 283 התרגילים. בפעם הראשונה זה חובה; אחר כך מריצים את זה רק אם קיבלתם קוד חדש ששינה את מבנה המסד (זה בטוח להריץ שוב בכל מקרה).

**חלון 2: השרת.**

```sh
pnpm dev
```

כשמופיעה שורה עם `http://localhost:3000`, השרת רץ. פותחים דפדפן ונכנסים לכתובת:

```
http://localhost:3000
```

### 4.3 מה רואים בפעם הראשונה

**ההתלבטות: למה אין מסך כניסה?**
בהרצה מקומית, בלי שהוגדרה סיסמה, האפליקציה פתוחה בכוונה: לא צריך להתחבר כדי לבדוק אותה. בשרת אמיתי זה הפוך, ראו סעיף 6.

המסלול בפעם הראשונה:

1. מסך הבית. לוחצים על הכפתור הראשי.
2. אישור תנאי שימוש ומדיניות פרטיות.
3. שאלון בריאות קצר.
4. בוחרים מקום וזמן, ומקבלים אימון: חימום, משחקון אחד או יותר, ושחרור.
5. מסיימים ומגיעים לסיכום.

**איך בודקים במובייל?** האפליקציה בנויה לטלפון. בדפדפן על המחשב לוחצים F12 (או Cmd+Option+I במק), ואז על האייקון של הטלפון בסרגל שנפתח. הדף יוצג ברוחב של טלפון.

### 4.4 עצירה

בכל אחד משני החלונות לוחצים Ctrl+C. קודם את השרת, אחר כך את המסד. הנתונים נשמרים.

### 4.5 אופציונלי: להפעיל את מסך הכניסה גם מקומית

אם רוצים לבדוק את מסך הכניסה כמו שהוא יהיה בשרת האמיתי, יוצרים בתיקיית הפרויקט קובץ בשם `.env.local` עם שורה אחת:

```
APP_PASSWORD="סיסמה-ארוכה-שבחרתם"
```

מפעילים מחדש את `pnpm dev`. מעכשיו תתבקשו להכניס את הסיסמה הזו. הקובץ הזה לא נשמר ב־Git (הוא ברשימת ההתעלמות), ולכן הסיסמה לא תדלוף למאגר. כדי לחזור למצב פתוח, מוחקים את הקובץ.

## 5. דרך ב': הרצה בענן של GitHub (Codespaces)

מתאים למי שלא רוצה להתקין כלום על המחשב. דורש חשבון GitHub עם גישה למאגר.

1. נכנסים לדף המאגר ב־GitHub. לוחצים על הכפתור הירוק "Code", על הלשונית "Codespaces", ואז "Create codespace on main". GitHub פותח חלון בדפדפן שנראה כמו עורך קוד, ובתחתיתו טרמינל. ההכנה לוקחת כמה דקות.
2. בטרמינל מקלידים:

   ```sh
   pnpm cloud:setup
   ```

   זה מרים מסד זמני, מכין את הטבלאות וטוען את התרגילים. בפעם הראשונה זה גם יוצר סיסמת כניסה לסביבה הזו.
3. ואז:

   ```sh
   pnpm cloud:dev
   ```

   הטרמינל ידפיס שורה עם הכתובת של התצוגה המקדימה. לוחצים עליה, או פותחים את הלשונית "Ports" בעורך ולוחצים על הגלובוס ליד פורט 3000.
4. כאן כן יש מסך כניסה. כדי לראות את הסיסמה מקלידים, בטרמינל נוסף:

   ```sh
   pnpm cloud:password
   ```

   הסיסמה הזו טובה רק לסביבה הזו. לא שולחים אותה לאף אחד ולא מעתיקים אותה למקום אחר.

**ההתלבטויות בדרך הזו:**

- **הסביבה "נוקתה" ואין יותר נתונים.** Codespaces מוחק סביבות שלא היו בשימוש זמן מה. המסד נמצא בתיקייה `.cloud` בתוך הסביבה, ולכן הוא נמחק איתה. זה בסדר: זו סביבת ניסוי. מריצים שוב את שני הצעדים.
- **שגיאה "Use a clean cloud checkout: .env already exists".** מישהו יצר קובץ הגדרות ידני בסביבה. הסקריפט מסרב להמשיך כי הוא לא רוצה להתחבר בטעות למסד אמיתי. מוחקים את הקובץ שמוזכר בשגיאה ומנסים שוב.
- **שגיאה "Port … is occupied".** כבר רץ שרת מהרצה קודמת. לוחצים Ctrl+C בטרמינל שבו הוא רץ, או סוגרים את הטרמינל, ומנסים שוב.

## 6. דרך ג': שרת אמיתי לאימון בטלפון (Railway)

זו הדרך היחידה שבה אפשר לפתוח את האפליקציה בטלפון בחדר כושר, ולכן זו הדרך של "האימון האמיתי" שבו הבעלים מאשר את המוצר.

ההוראות המדויקות, כפתור אחרי כפתור, נמצאות ב־[docs/ops/RAILWAY.md](RAILWAY.md). כאן רק ההתלבטויות שצריך להכריע לפני שמתחילים:

**התלבטות 1: שירות חדש או האתר החי?**
תמיד שירות חדש, עם מסד חדש. האתר החי רץ מהמאגר הקודם ומכיל נתוני משתמשים אמיתיים. הקמת שירות חדש לצד האתר החי לא נוגעת בו, ואפשר למחוק אותה בכל רגע. חיבור של המאגר הזה למסד החי הוא שלב 11 ב־[התוכנית](../PLAN.md) ודורש גיבוי והחלטה מפורשת של הבעלים.

**התלבטות 2: איזו סיסמה?**
בשרת אמיתי חובה להגדיר `APP_PASSWORD`. בלי זה השרת מסרב לענות בכוונה (שגיאה 503), כדי שאף אחד לא יפתח בטעות אפליקציה פתוחה לכל העולם. בוחרים סיסמה ארוכה, שונה מזו של האתר החי, ושומרים אותה במנהל סיסמאות. לא כותבים אותה בקוד, במסמך במאגר או בהודעת צ'אט.

**התלבטות 3: מה עם `AUTH_SECRET`?**
זה מחרוזת אקראית ארוכה שחותמת את "עוגיית הכניסה" (מה שגורם לטלפון לזכור שנכנסתם). בלי זה החתימה נגזרת מהסיסמה, ואז כל החלפת סיסמה מנתקת את כל המכשירים. מומלץ להגדיר. אפשר לייצר מחרוזת אקראית בכל מחולל סיסמאות, באורך 32 תווים לפחות.

**התלבטות 4: כניסה עם גוגל?**
לא צריך לסביבת ניסיון. בלי משתני גוגל נכנסים בסיסמה בלבד, וזה מספיק לאימון אמיתי. חיבור גוגל שייך לשלב הייצור.

**התלבטות 5: איך יודעים שזה עבד?**
בלוגים של הפריסה הראשונה ב־Railway מחפשים שתי שורות: המיגרציות הסתיימו, ו־283 תרגילים נטענו. אחר כך פותחים את הכתובת בטלפון, מכניסים את הסיסמה, מאשרים תנאים ושאלון בריאות, ובונים אימון. אם זה עובד, הסביבה מוכנה.

**התלבטות 6: גיבוי?**
בסביבת הניסיון אין גיבוי אוטומטי, וזה בסדר כי הנתונים בה הם נתוני ניסיון. גיבוי חובה רק לפני המעבר לייצור, לפי [מדריך האחסון](STORAGE.md).

שימו לב: כל דחיפה של קוד לענף `main` במאגר הזה תעדכן את סביבת הניסיון אוטומטית. זה נוח, אבל פירושו שגרסה שבורה ב־`main` תשבור את הסביבה בטלפון.

## 7. איך יודעים שגרסה "מוכנה"

לפני שמעלים קוד לשרת, או לפני שאומרים "זה עובד", מריצים ארבע בדיקות בטרמינל (בתיקיית הפרויקט, אחרי `pnpm install`):

```sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

| פקודה | מה היא בודקת | כמה זמן |
| --- | --- | --- |
| `typecheck` | שהקוד עקבי עם עצמו (אין מקום שמצפה למספר ומקבל טקסט) | כחצי דקה |
| `lint` | כללי סגנון וטעויות נפוצות | כחצי דקה |
| `test` | הבדיקות האוטומטיות של ליבת האימון | כדקה |
| `build` | שהאפליקציה מתקמפלת לגרסה שאפשר להעלות לשרת | כמה דקות |

כל אחת מסתיימת בלי שורות אדומות: הגרסה עברה. אחת נכשלה: הגרסה לא מוכנה, ומעתיקים את השגיאה למי שמתקן.

לפי [הוראות העבודה](../../CLAUDE.md), גם ארבע בדיקות שעוברות אינן קבלה. "מוכן" פירושו גם שהמסלול נבדק בדפדפן ברוחב טלפון מהמסך הראשי עד הסיכום, והקבלה הסופית היא אימון אמיתי של הבעלים בטלפון.

יש גם בדיקה חיה (`pnpm check:live`) שמדמה ניתוק, שגיאת שרת ולחיצה כפולה. היא **מוחקת נתונים** ולכן רצה רק מול המסד המקומי ועם אישור מפורש. ההוראות ב־README. לא מריצים אותה מול שרת אמיתי.

## 9. מה לא עושים

- **לא נוגעים באתר החי.** הוא במאגר אחר, עם מסד אחר. כל מה שכאן נפרד ממנו.
- **לא מעלים לייצור, לא משנים את מבנה המסד ולא משנים נוסח משפטי** בלי אישור מפורש של הבעלים. זה כתוב ב־[CLAUDE.md](../../CLAUDE.md) וזה חל גם על אנשים.
- **לא שומרים סיסמאות במאגר.** קבצי `.env` לא נכנסים ל־Git. אם סיסמה הופיעה בטעות בקומיט, בהודעה או במסמך, מחליפים אותה.
- **לא מריצים `pnpm check:live` או `pnpm db:reset` מול שרת אמיתי.** שתיהן מוחקות נתונים.
- **לא מתקינים עם npm או yarn.** רק pnpm. שימוש בכלי אחר יוצר קבצים מיותרים ושגיאות מבלבלות.

## 10. סיכום של דקה

על המחשב, פעם אחת: להתקין Node.js 22, להוריד את הקוד, `corepack enable`, `pnpm install`.
בכל פעם: חלון 1 `pnpm db:local`, חלון 2 `pnpm db:setup` (בפעם הראשונה) ואז `pnpm dev`, דפדפן ב־localhost:3000.
בענן: Codespaces, `pnpm cloud:setup`, `pnpm cloud:dev`.
בטלפון: Railway לפי [RAILWAY.md](RAILWAY.md), עם שירות ומסד חדשים וסיסמה חדשה.
לפני שאומרים "מוכן": ארבע הבדיקות בסעיף 7, ואז בדיקה בדפדפן ברוחב טלפון.
