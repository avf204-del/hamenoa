# אחסון, גיבוי ושחזור

עודכן: 20.9.2026. ההוראות מתייחסות לקוד המקומי הנוכחי; התקנת הקוד בשירותי הענן היא פעולה נפרדת.

## מקורות סמכותיים

| מידע | מקור | מה מגבה אותו |
| --- | --- | --- |
| משתמשים, אימונים, רישומים וכיולים | PostgreSQL | `db:backup`, בשני יעדים נפרדים |
| תרגילים ותיוג | `data/tagging.yaml` ומקטעי `data/training-types` בגיט | Git וארכיון התוכן |
| מדיה שפורסמה | `public/exercises`, `public/warmup` בגיט | Git וארכיון התוכן |
| מקורות, תמונות מקור ורישיונות | `../storage/content-sources` | גיבוי התוכן המקומי ויעד נוסף כשהוגדר |
| תוצרי בנייה ותלויות | `.next`, `node_modules` | נוצרים מחדש; אינם גיבוי |

עריכת התרגילים דרך הממשק מותרת בפיתוח בלבד. קובץ המקור נכתב בהחלפה אטומית, ורק אחר כך מסונכרן למסד. כתיבות מתוך העורך רצות בתור. אם המסד נכשל, העריכה נשארת בקובץ והמשתמש מקבל שגיאה עם הוראת סנכרון. יש לשמור את הקובץ בגיט לפני פריסה; גיבוי המסד לבדו אינו מפרסם תיקון תוכן בגרסה הבאה.

## גיבוי המסד

`pnpm db:backup` קורא את הטבלאות מתוך טרנזקציית `REPEATABLE READ READ ONLY`. הקריאה היא בעמודים והדחיסה בהזרמה, כדי לא לטעון את כל המסד לזיכרון. גילוי הטבלאות נעשה לפני הקריאה, ולכן גיבוי שלפני מיגרציה אינו נכשל בשל מודל חדש או עמודה שעדיין חסרה.

הקובץ נכתב זמנית, מפורסם רק בסיום, ומקבל חתימת `.sha256`. הגיבויים החדשים נוצרים בהרשאות בעלים בלבד. דחיסה אינה הצפנה: יש להגן על כונן הגיבוי ועל הרשאות הגישה ליעד החיצוני בהתאם למידע שבתוכו.

```sh
pnpm db:backup
pnpm db:backup --dir /your/backup/directory --keep 30 --source manual
```

טבלאות שחסרות במסד נרשמות ב־`missingTables`; זה אינו גיבוי מלא ולכן אינו נרשם כהצלחה בחיווי. במסך הניהול מוצגים מצב מקומי ומצב ענן בנפרד. כישלון נרשם כ־`failed` כשהמסד מאפשר זאת; כשהמסד אינו זמין, היעדר הצלחה טרייה והלוג הם מקור האבחון. אין לסמן את שני הנתיבים כתקינים בגלל הצלחת אחד מהם.

## שחזור

לפני שחזור מאמתים את יעד `DATABASE_URL`, מריצים עליו מיגרציות ומשתמשים תחילה במסד מבודד. השחזור בודק חתימה אם קיימת, פורמט ומבנה לפני חיבור וכתיבה. גיבוי ישן ללא חתימה נתמך עם הודעה מפורשת. גיבוי חלקי מחייב `--allow-partial` לאחר בדיקה.

```sh
DATABASE_URL="$RESTORE_DATABASE_URL" pnpm db:restore /path/to/engine-backup.json.gz
```

`--force` מאפשר כתיבה למסד מאוכלס. זו פעולת **מיזוג לפי מזהה**: רשומות שלא נמצאות בגיבוי אינן נמחקות. לקבלת עותק של נקודת הזמן משחזרים למסד ריק. השחזור טרנזקציוני, מיישר מפתחות עסקיים, ומתבטל במלואו בכישלון.

תרגול השחזור האוטומטי המקומי: `pnpm exec vitest run tests/db-restore.test.ts`. הוא מפעיל מסד זמני ומשחזר דרך כלי ה־CLI האמיתי. בנפרד יש לבצע מדי חודש תרגול עם גיבוי אמיתי למסד מבודד, לרשום מועד, קובץ, סכומים ותוצאת אימות, ולמחוק את מסד התרגול בסיום לפי מדיניות המידע. בדיקת חתימה אינה הוכחה לשחזור אפליקטיבי מלא.

## גיבוי תוכן

הנתיב המשותף כבר הוכן מקומית: `forceapp/storage/content-sources`. הקבצים הקודמים הועברו אליו לאחר אימות SHA-256, והנתיבים הישנים ב־`app` וב־`content` נשמרו כקישורים. המיקום אינו חלק מגיט ואינו תלוי בענף עבודה.

```sh
pnpm content:verify
pnpm content:archive
pnpm content:backup
```

`content:archive` שומר גם גרסאות קודמות ומקורות שכבר אינם זמינים במיקום ההפקה. קבצים נשמרים לפי חתימה, והאינדקס מתחלף אטומית. נעילת `.archive-lock` מונעת כתיבות מתנגשות בין תיקיות עבודה. אם תהליך נקטע ונשארה נעילה, מוודאים שאין תהליך ארכוב פעיל לפני הסרת תיקיית הנעילה הריקה.

`content:backup` יוצר ארכיון של האובייקטים והאינדקס, מחלץ לתיקייה זמנית ובודק כל אובייקט לפני רישום הצלחה. החתימה מחושבת בהזרמה. המניפסט משמר את שמות ומיקומי המקור; בשחזור מחלצים ליעד מבודד ומעתיקים ממנו רק נתיבים נבחרים שנבדקו, לא נתיבים מוחלטים באופן עיוור.

להעתקה ליעד נוסף: להגדיר `CONTENT_BACKUP_MIRROR` לנתיב בבעלות המפעיל ולהריץ `pnpm content:backup`. ההעתקה נבדקת בחתימה. `differentDevice` מזהה התקן אחר בלבד; תיקיית ענן על אותו דיסק מחייבת גם אימות שהסנכרון הושלם אצל הספק. **נכון לביקורת: לא נמסר יעד חיצוני ולא נטען שנוצר עותק מחוץ למחשב.**

## שמירה ופינוי

| סוג | מדיניות |
| --- | --- |
| גיבויי מסד רגילים | עד 30 קבצים ועד 30 יום; חתימות נמחקות יחד עם הקובץ |
| צילומי JSON ידניים וקובצי SQLite היסטוריים בתיקיית backups | 30 יום לפי מועד שינוי; `backup:inventory` מציג מועמדים ו־`--apply` מבצע |
| גיבויי תוכן | שלושת האחרונים; `content:backup --prune` מפנה ישנים רק לאחר גיבוי מאומת חדש |
| אובייקטי מקור ורישיונות | נשמרים; אין ניקוי אוטומטי של המקורות |
| `.next` | אפשר לפנות כשאין שרת פעיל מאותה תיקייה |
| תיקיות worktree | בדיקת Git וקבצים בלתי מנוהלים לפני הסרה; לא מוחקים מאגרי מידע יחד איתן |

הגיבוי היומי המקומי מפעיל גם את ניקוי הגיבויים האישיים שפג תוקפם. חסר קובץ סביבה או חסר `DATABASE_URL` מחזירים כישלון ולא הצלחה מדומה. אין אפשרות לבצע ניקוי במחשב כבוי; יש להביא זאת בחשבון בהתחייבויות התפעול. גיבויי תוכן אינם חלק מגיבוי הנתונים האישיים.
